# Building Plugin.Maui.Intercom

This document provides guidance for building the Plugin.Maui.Intercom repository.

## Prerequisites

| Tool | Version | Needed for |
|------|---------|-----------|
| .NET SDK | 10.0.1xx (pinned in `global.json`) | everything |
| MAUI workloads | `dotnet workload install maui-ios maui-android` | plugin, sample |
| JDK | 17 | Android binding (Gradle) |
| macOS + Xcode | Xcode 26+ (CI pins 26.6) | iOS binding, iOS app builds |

The iOS binding is generated by [swift-dotnet-bindings](https://github.com/justinwojo/swift-dotnet-bindings) (`SwiftBindings.Sdk`, pinned in `global.json` under `msbuild-sdks`) and **can only be built on macOS**. Windows and Linux can build the Android binding, the managed plugin, and the Android flavor of the sample.

## Building

### Cross-platform projects (any OS)

```bash
# Android binding
dotnet pack src/android/Intercom.Android.Binding/Intercom.Android.Binding.csproj -c Release -o artifacts/packages

# Solution (plugin + sample + android binding; iOS binding is intentionally excluded)
dotnet build Plugin.Maui.Intercom.slnx
```

Note: restoring `Plugin.Maui.Intercom.csproj` needs a resolvable `Plugin.Maui.Intercom.iOS.Binding` package — either the published one on nuget.org, or a locally packed one added to a NuGet source (see below).

### iOS binding (macOS only)

```bash
eng/generate-ios-binding.sh --output artifacts/packages
```

The script validates the toolchain (macOS, Xcode 26+, .NET 10), prints all pinned versions, cleans previous generated output, regenerates the binding from the vendored `Intercom.xcframework`, and packs `Plugin.Maui.Intercom.iOS.Binding`.

### Main package against locally packed bindings

```bash
cat > /tmp/local-nuget.config <<'EOF'
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <clear />
    <add key="local" value="ABSOLUTE_PATH_TO/artifacts/packages" />
    <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
  </packageSources>
</configuration>
EOF
dotnet restore src/Plugin.Maui.Intercom/Plugin.Maui.Intercom.csproj --configfile /tmp/local-nuget.config
dotnet pack src/Plugin.Maui.Intercom/Plugin.Maui.Intercom.csproj -c Release --no-restore --output artifacts/packages
```

## Validating packages

```bash
eng/validate-packages.sh --version <version> --feed artifacts/packages   # nupkg content assertions
eng/test-consumer.sh    --version <version> --feed artifacts/packages    # clean-room consumption test (macOS)
```

## Updating the pinned Intercom iOS SDK

```bash
eng/update-intercom.sh <version> [<expected-sha256>]
eng/generate-ios-binding.sh
```

## Sample app

```bash
dotnet build src/sample/MauiSample.csproj -f net10.0-android -t:Run   # Android
dotnet build src/sample/MauiSample.csproj -f net10.0-ios -t:Run       # iOS (macOS only)
```

Sample credentials go in `src/sample/appsettings.Development.json` (git-ignored); the app compiles and runs without them, but Intercom interaction requires real keys.

## Windows notes

Long-path support is no longer required: the Swift-interface juggling that used to overflow `MAX_PATH` was removed together with the old Objective Sharpie–style binding. The iOS binding simply does not build on Windows — use CI or a Mac.
